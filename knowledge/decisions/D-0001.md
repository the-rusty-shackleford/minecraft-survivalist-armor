# D-0001 — The kit system

**The ask.** nfx's handoff (`knowledge/sources/ARMOR-MOD-SPEC.md`, §1, §2, §10, §13, §14). Seven
craftable cosmetic kits, applied at the smithing table the way vanilla trims are. A kit changes how a
piece looks and nothing else. A trim must still show, and uninstalling must never lose a piece.

**Decision.**

- **A kit is an item.** One `SmithingTemplateItem` per kit (`survivalistarmor:roadplate_kit`, …).
  The smithing screen takes its ghost icons and its "Applies to / Ingredients" tooltip from that
  class. Its armour-stand preview wears the result, so a kit is seen before it is taken.
- **Our own recipe type**, `survivalistarmor:kit_smithing`, one JSON per kit:
  - template: the kit;
  - base: an `ArmorItem` in `#minecraft:trimmable_armor` (the four slot tags; elytra is in none) that
    the server's blacklist doesn't name;
  - addition: a per-kit ingredient, the cost only. The palette comes from the base piece's own armour
    material.
- **On the piece: one data component**, `survivalistarmor:kit`, holding the kit's id as a
  `ResourceLocation` and nothing else.
  - The result is `base.copyWithCount(1)` with it set, so every other component is kept:
    enchantments, damage, name, trim, dye, attribute modifiers.
  - Swapping a kit is setting the component again.
  - The item, its stats and its name never change.
- **Taking a kit off**: the piece and shears in the crafting grid. The piece comes back without the
  component, and the shears come back with one point of damage. Not the grindstone, which strips
  enchantments.
- **The template is consumed**, as vanilla's are. A server option keeps it. `SmithingMenu.onTake`
  shrinks all three slots unconditionally, so the option is a mixin there.
- **Drawn by one hook.**
  - **Worn:** a cancellable injection at the head of `HumanoidArmorLayer.renderArmorPiece`, acting
    on kitted pieces only. That one layer draws armour on players, mobs and their babies, armour
    stands, the smithing preview, Set It Down's invisible stands and Serfdom's villagers.
    - EMF 3.2.4's own armour-layer mixins are inert on 1.21.1 (they target `CancelTarget`), so
      cancelling early strands no state.
    - Un-kitted pieces keep Armored Legacy's models.
  - **First person:** after the sleeve, at the tail of `PlayerRenderer.renderHand`.
  - **The trim:** each trim-eligible face also carries its projection onto its part's vanilla armour
    box in the 64×32 layout, and the trim is drawn there exactly as vanilla draws it. The kit's own
    texture is therefore laid out freely, asymmetric arms included. Lenses, hoses, canisters,
    pouches, straps, buckles, rivets and tape take no trim.
- **Uninstalling.**
  - A stack naming an unregistered component loads with only that entry dropped. `ItemStack.parse`
    ends in `resultOrPartial`, and DFU 8.0.16's `DispatchedMapCodec` and `OptionalFieldCodec` both
    keep a partial result.
  - A kitted piece therefore comes back plain and loses nothing else. The kit items themselves
    vanish, as any removed mod's items do.

**Alternatives rejected.**

- *Bending `SmithingTrimRecipe`.* It is hard-wired to the trim component (the spec says the same).
- *The kit kept in `minecraft:custom_data`.* It would survive an uninstall as dead data. A registered
  component already drops cleanly (S1), and it syncs and reads as a typed value.
- *One item for every kit, the kit named in a component.* Recipe viewers and the trim-template
  convention both want an item per kit.
- *The grindstone for removal.* It strips enchantments.
- *Generated item-model JSONs.* See D-0003.

**Verification.**

- S1, 2026-10-09: `UninstallGameTests`, 9 cases, green. A save whose kit key is renamed to one no
  registry holds loads the plain piece with every other component equal, wherever the stack is
  saved:
  - on its own, and in a shulker box's or a bundle's contents;
  - in a chest, an item frame, a dropped item;
  - on an armour stand and a zombie;
  - in a player's inventory and chest slot.
  
  The first case also checks that a strict read refuses the save. A mutant expecting the kit kept
  failed all 9.
- The rest, in Phase 1: `KitSmithingTests`, `KitRemovalTests`, `CosmeticOnlyTests`, `SyncTests`, and
  the booth's wearers.
