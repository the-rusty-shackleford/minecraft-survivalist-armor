# D-0003 — Kitted item models at runtime

**The ask.** nfx (§11): a kitted piece is 3D wherever the item exists (inventory, hands, the ground,
item frames), matching the worn piece. nfx proposed "a few hundred generated model JSONs", one per
kit, piece and trim material, chosen by an `ItemProperties` predicate.

**Why not JSON.** In this pack it would never show:

- Armored Legacy replaces `assets/minecraft/models/item/<armor>.json`, and resource packs outrank a
  mod's own resources.
- Armored Legacy also ships 28 `assets/minecraft/items/*.json` definitions, which Modefite reads on
  1.21.1. Modefite's `HeldItemMixin` swaps the model at the head (cancellable) of
  `ItemRenderer.getModel`, `render` and `renderStatic(LivingEntity…)`, so overrides on the baked
  model are never consulted.
- Modded armour would need a JSON per item.

**Decision.**

- **One `BakedModel` per kit, piece and palette**, built from the kit's own Blockbench project at
  rest pose: real quads, the same geometry as worn. Built lazily and cached until the next resource
  reload.
- **MixinExtras `@WrapMethod`** (0.5.3 ships with NeoForge 21.1.248) on those three methods. It
  wraps them outside every other mod's injections, Modefite's included. For a kitted stack,
  `getModel` returns our model, and `render`/`renderStatic` draw it: camera transforms, quads, the
  trim, the glint. They never call through. Every other stack calls through.
- **The trim is drawn on the item** by the same projection as when worn (D-0001), with its real
  pattern. Vanilla's item icons show only the trim's material.
- **No flat sprite** for kitted pieces. Everything that shows an item draws it through
  `ItemRenderer`: recipe viewers, advancement icons, tooltips. The kit templates keep flat sprites,
  as trim templates do.
- **Set It Down** never uses an armour piece's item model. A piece set down is the worn piece on an
  invisible stand (its D-0003), so it is drawn by D-0001's hook. It measures that box per item,
  though, so it needs a patch to measure per components (Set It Down 1.1.1).

**Alternatives rejected.**

- *JSON overrides plus a predicate.* Unseen in this pack, as above.
- *Wrapping each armour item's baked model at `ModifyBakingResult`.* Modefite replaces the model
  before the overrides are asked.
- *Mixin priority to run ahead of Modefite's head injections.* It depends on the order mods are
  applied in; `@WrapMethod` sits outside them all.

**Verification.** S3: the booth with Modefite, Armored Legacy and 3D Default loaded shows the kit's
model in the gui, a hand, on the ground and in a frame, and an un-kitted piece unchanged.
